1. Inputs TUI per-file session breakdown drill-down. Pressing Enter on an attribution row shows which sessions loaded the file and at which tier, similar to the list→show pattern. Requires building a per-file-per-session evidence data pipeline and adding a View enum to the inputs TUI.
2. TUI tab error state. When a lazy data load fails (e.g., the inputs closure from `cclens list`), display an error message in the tab content area rather than silently staying on the current tab. The `Fn` loader allows retry, so the error state should offer a "press key to retry" affordance. Applies to all tab data loaders.
3. TUI tab loading state. When a tab's data is being loaded, show a loading indicator in the tab content area. Currently loads are synchronous and sub-50ms, but this becomes necessary when periodic background data refresh is added.
4. TUI background refresh for live session monitoring. Users should be able to watch sessions and costs update in real time without re-running cclens. Change detection can leverage the append-only nature of JSONL files: track `(path, mtime, file_size)` per session and only re-parse files whose metadata has changed since the last scan. For active sessions, seek to the previous byte offset and parse only new lines. Consider OS-level file notifications (kqueue on macOS, inotify on Linux via the `notify` crate) as an alternative to periodic polling, or as a complement — notify for responsiveness, periodic poll as a fallback for edge cases (NFS, moved files). Scope question: full re-discovery (new sessions, deleted sessions) vs. incremental update of known sessions — likely need both, but at different cadences (e.g., re-discover every 30s, re-parse active files on change or every 2–5s). Depends on TODO #3 for loading state UX during refreshes.
