1. Inputs TUI per-file session breakdown drill-down. Pressing Enter on an attribution row shows which sessions loaded the file and at which tier, similar to the list→show pattern. Requires building a per-file-per-session evidence data pipeline and adding a View enum to the inputs TUI.
2. TUI refresh: explore fs-notification-based change detection. The current 3s polling interval works but runs `discover()` (full project tree walk + per-file stat) every tick. If this becomes a problem for power users with large project trees, prefer switching to OS-level file notifications (`notify` crate: kqueue on macOS, inotify on Linux) over tuning the poll interval. Incremental parsing (seek to byte offset, parse only new lines) would also reduce reload cost for active sessions.
3. TUI refresh: surface refresh errors. All three refresh handlers silently drop loader `Err` results — the view stays on stale data with no feedback. Adding a status bar or brief toast area to the TUI would let transient errors surface without disrupting the view. Also consider: should a fingerprint-build failure (`fp_builder().ok()?` → `NoChange`) trigger a reload-anyway instead of skipping?
4. TUI: reduce `run_tui` / `run_event_loop` / `drain_pending_loads` arity and duplication. `run_tui` and `run_event_loop` take 9+ parameters (suppressed via `#[allow(clippy::too_many_arguments)]`), and the five refresh handlers in `drain_pending_loads` share ~30 lines of near-identical boilerplate (suppressed via `#[allow(clippy::too_many_lines)]`). Likely shape: bundle loader closures + fingerprint into a context struct, and extract a generic `refresh_with_fingerprint` helper parameterized over the loader and result-mapper.
